# exp4 主流结构优化与代表性小批量测试

## 1. 数据分布与优化范围

统计对象为本地三个1000题评估文件，不扩展为对原始完整benchmark的统计结论。

| 数据集 | 已标明的主要类型／拓扑 | 题数 |
|---|---|---:|
| HotpotQA | bridge／comparison | 811／189 |
| 2Wiki | compositional／comparison／bridge_comparison／inference | 413／244／235／108 |
| MuSiQue | 2跳链／3跳链／3节点合流／4跳链／合流后延伸／链与另一根合流 | 518／243／73／108／27／31 |

Hotpot桥接占81.1%，2Wiki前三类合计89.2%，MuSiQue线性链合计86.9%。本轮关注链式支撑与完整比较分支，不为零散个例增加实体专用规则。Hotpot这1000题的`level`全部为`hard`，因此不能用这个字段排除少量所谓hard case；所有主类型仍进入采样。

运行时路由只读取问题文本，不读取dataset名称、type、答案、supporting facts或分解内容。离线结构标注只用于采样与分层评价。沿用已授权的benchmark hop规则：MuSiQue逐题跳数，另两个数据集的既有prior。

## 2. 四个预先固定的方案

| 配置名 | 实际改动 |
|---|---|
| structure_routed | 明确比较／多对象属性问题扩大规划容量；链式与未知结构调用原exp4提示词和节点预算；使用原exp4选择机制 |
| support_tail | 在原选择完成后，最多补入2篇同winning branch的祖先引用文档到第6–10位；原Top5严格保留 |
| support_swap | 在上述保护外，最多用祖先证据替换1篇未验证、无独占goal的明显重复文档；同标题、Jaccard≥0.85、数字及否定信息一致才可替换 |
| structure_support | 问题结构路由与support_swap共同启用 |

祖先保护仅在子节点的文档已经位于原Top5、完整祖先引用存在且字面检查通过时触发。要求引用为原文连续子串、答案为引用中的字面内容、confidence有限且≥0.85、绑定属于winning branch。这里的confidence来自LLM，不是校准过的正确率；字面引用也不是任意关系的语义证明。

缺证明、错分支、循环或超预算时安全跳过，不删除普通候选。被替换文档保留在尾部。支持保护不新增LLM或检索请求；不重新启用上一轮typed binding、全局selection或adaptive扩量。

只有support_tail可以保证本次后处理前后R@1–5不变；其他方案仍可能影响Recall。保留完整输入文档集合不等于最终截取Top200的集合不会改变。改进必须由实测判断。

问题文本路由的全1000题离线检查：Hotpot170题扩展／830题沿用原规划；2Wiki470／530；MuSiQue11／989。MuSiQue869条线性链全部沿用原规划；未知合流问题保留原路径。这是路由覆盖率，不是性能收益，也不代表80–90%问题都会触发新操作。

## 3. 代表性采样方案

每个数据集60题筛选、另外30题确认，排除之前三轮各数据集共216道已规划的开发题。确认题还排除本次60题筛选；两题smoke从筛选中选不同结构，用途仅为集成检查。

主层：Hotpot的2种type、2Wiki的4种type、MuSiQue的6种依赖拓扑。按剩余池比例分配名额，稀有主层尽量至少2题；次级平衡跳数、gold文档数、末端属性及它们的交叉组合，使用随机并列决策。抽样不读取先前召回分数、检索成功与否或答案值。

MuSiQue的`#n`引用代表分解项位置，DAG规范父节点顺序，避免把相同结构虚拆为不同类型。同标题但不同段落的gold不合并。分解问句末端属性只用于离线样本结构统计，绝不传给检索器。

输出每个数据集的总体、可用池、筛选、确认分布，样本索引，过采样类别，未覆盖类别及权重。保证主类型覆盖不等于所有语义和稀有交叉组合都覆盖；60/30题还不足以证明统计显著或完全无偏。

## 4. 指标与验收

同时保存：

- 原始样本Recall、All gold比例及每题Top10／Top200。
- 按原1000题主层比例校准的所有Recall。
- 按该阶段可用池主层比例校准的Recall。
- 各主层的独立Recall和完整证据命中率。

主层校准权重为`N_h/(N*n_h)`，全部样本权重之和为1。它修正主类型比例与稀有类别过采样，但不是精确的逆包含概率，不能消除次级平衡、开发样本排除或少量样本造成的全部偏差。

本轮预先固定以原1000题主层校准的R@5/R@10做目标判断，同时保留raw_sample_assessment。增益仍为至少0.04、任意指标退化不超过0.01；容许最多两个例外且每数据集须有达到增幅的指标，门槛不因上限或实测改变。达到目标也仅是探索性候选，不能直接写为全量／论文结论。

四个单独／组合配置都在同批60题上测试。不再自动生成额外组合；筛选后最多两候选在同批新30题与新原exp4对照确认。若均未显示受保护的正向信号，仍确认探索分数最高的一候选，但不称为有效。不会自动启动全量或QA。

## 5. 复现与保存

公共索引复用`outputs/3multi_hop_datasets_results_10_5/shared_indexes`，Qwen3-Embedding-8B batch=4、LLM/OpenIE并发=8、2048输出上限、thinking关闭。原生HippoRAG源码保持原样。

```bash
bash scripts/run_exp4_round2.sh --mode all \
  --run-tag structure_representative --sampling-policy representative \
  --screen-size 60 --confirm-size 30 --screen-seed 342 --confirm-seed 442 \
  --variants structure_routed,support_tail,support_swap,structure_support
```

固定9组两题smoke＋15组60题筛选；随后6或9组30题确认，共30或33组。原有结果不覆盖。

- 摘要：`metadata/exp4_round2_selection_structure_representative/selection.json`。
- 采样报告：同摘要目录下`sampling/{dataset}.json`。
- 实测结果：`_exp4_round2_trials_structure_representative/`。
- 日志：`logs/run_exp4_round2.log`。

所有算法、脚本、数据、索引、先前样本和采样报告均保存哈希。每组验证完成后只清理私有索引副本，保留结果、trace与校验凭据。各改进共用阶段原exp4完成后的缓存快照；热缓存耗时不作为公平冷缓存效率结论。

## 6. 启动前校验

199项相关CPU测试通过：148项证据检索、8项代表性采样、6项问题结构路由、37项实验脚本。包含首次启动创建采样报告、续跑样本／报告完整性校验、support参数转发和完美Recall的浮点边界。Shell语法与diff检查通过。

正式命令先执行9组两题实测，原exp4与其缓存重放需Top10一致，再进入60题筛选。CPU测试通过不等于四方案达到增益目标，最终状态以本轮selection.json与实测report.json为准。
