# 三多跳数据集的公共索引与检索对照

## 范围和固定配置

使用 `/root/datasets` 中 HotpotQA、2WikiMultiHopQA、MuSiQue 三个本地文件，各 1000 题；这是本地文件的全量，不代表公开数据集全部样本。

每个数据集运行 `hipporag2`、`pathcondrag_original`、`exp4_dependency_binding` 三组，均为 `eval_mode=retrieve`，不运行最终 QA。exp4 中为了绑定后续检索而生成的中间答案仍属于检索。

| 设置 | 值 |
|---|---|
| LLM | 本地 Qwen3-8B，vLLM API `127.0.0.1:8035/v1` |
| embedding | `/root/models/Qwen3-Embedding-8B` |
| embedding batch | 4 |
| 索引抽取并发 / 检索 LLM 并发 | 8 / 8 |
| NER 输出上限 | 512 |
| triples / 检索 LLM 输出上限 | 2048 |
| thinking | 关闭 |
| 抽取提示词 | `optimized` |
| 索引验证模式 | `openie_validation_mode=structural`，默认 |
| 索引失败策略 | `openie_strict=false` |
| 检索候选 / 每题详细结果 | 200 / 10 |

跳数沿用当前正式 reader：MuSiQue 使用逐题分解长度 2/3/4；HotpotQA 和 2Wiki 使用明确记录的 **dataset prior 2**。2Wiki 中 235 题有 4 个支撑文档，文档数量不自动等于串行推理深度。本轮不改变这一算法设定，manifest 同时保存支撑文档数和跳数来源，避免混淆。

## 脚本入口

```bash
cd /root/PathCondRAG
bash scripts/run_multi_dataset_retrieval.sh
```

脚本先完成三个独立公共索引，再顺序运行九组检索。索引构建使用 PathCondRAG 的 `scripts/build_shared_index.py` 和 `src/pathcondrag/index` 抽取实现。HippoRAG2 的检索调用原入口；本流程不会修改 `/root/baseline/HippoRAG` 源码。

默认结构模式下，普通成功 chunk 通常只有 NER 1 次、三元组 1 次逻辑请求。三元组返回经过本地格式、字段和正常结束状态检查，不运行语义 audits、compact 或 atomic 恢复。格式错误或截断才追加三元组请求；当前结构 profile 下每个 chunk 的三元组逻辑 infer 累计预算为 3 次，包括该 profile 的检查点续跑历史，**不包含 NER 和底层 HTTP transport retries**。NER 保留原有固定 512 输出及失败恢复合同；三元组 2048、thinking 关闭均不变。

`--openie-validation-mode source_verified` 可显式选择原文证据核验模式，其额外 LLM 核验和恢复开销高于默认模式。验证模式和 `openie_strict` 相互独立：严格发布也可使用结构检查，宽松发布也可使用原文核验。结构检查通过只说明输出满足当前本地合同，**不能证明关系的语义保真**；结果和质量 profile 会明确记录 `validation_scope=structural`、`semantic_verified=false`。

默认要求 vLLM 已启动，日志位于本次输出目录的 `logs/vllm.log`。另一个服务或目录可通过 `--llm-base-url`、`--vllm-log` 指定。`rag` 的 Qwen3 依赖通过 `/root/.cache/pathcondrag/runtime_deps_qwen3_tf4513` 独立覆盖，不更改 conda 主环境。

## 复用与容错

公共索引通过完整 corpus 身份和资产哈希验证后冻结。每组图和向量使用 hardlink，抽取元数据与请求缓存独立复制；各方法从同一缓存快照起步。构建阶段的 SQLite 进度日志不复制到检索组，减少磁盘占用。

重新运行同一脚本会复用已冻结公共索引并跳过已验证结果。数据或冻结资产变化会报出明确错误，避免悄悄使用不对应的索引。新建库过程的未完成抽取 checkpoint 可以继续；已完成索引不会被自动覆盖。

`openie_strict=false` 允许抽取重试后仍失败的 chunk：保留原文和段落向量，将失败关系明确排除出图，记录实际失败数，然后继续后续检索。它不会把失败伪装为成功，也不会掩盖文件损坏、显存溢出或服务不可用。某一组发生其他错误时，记录错误并继续其他可运行组；有失败时最终退出码非零。

### 当前 HotpotQA 检查点恢复

HotpotQA 已有的 NER 结果和首次原始三元组响应用于此次显式迁移复用。迁移保存原检查点备份，并在 `metadata/hotpotqa/structural_migration_report.json` 记录身份检查、复用与待处理数量及备份位置。NER 提示词、恢复合同和 512 输出上限保持一致；已有完成的 NER 不重复请求。

首次原始三元组满足本地结构检查且正常结束时复用；此前语义 audits、compact 或 atomic 产生的衍生结果不会被当作新结构模式已经批准的关系。仍有问题的原始抽取进入新 profile 的有限重试，最终失败按 `openie_strict=false` 明确排除关系并保留段落。迁移前已发生的请求成本保留历史记录，与新结构 profile 的 3 次三元组预算分开统计。迁移不绕过语料身份、检查点完整性和最终图/向量一致性验证。

## 同一脚本的小样本检查

```bash
OUT_ROOT=/root/PathCondRAG/outputs/3multi_hop_datasets_results_10_5/_smoke_structural \
  bash scripts/run_multi_dataset_retrieval.sh --smoke
```

每个数据集选 2 条原问题及全部对应 gold 文档，并补充完整原文到 20 个独立段落，从建索引到三种检索完整执行。MuSiQue 覆盖 2 跳和 4 跳。候选预算仍为 200，测试库不足 200 段时自然导出全部 20 段；正式全库导出 200 段。测试语料缩小，不用于估计全量性能。

2026-10-05 的结构模式实测已完成全部三索引及九组检索：每个索引 20 个完整 chunk，最终抽取失败均为 0。HotpotQA、2Wiki、MuSiQue 的索引 LLM 请求分别为 41、40、40 次，HTTP transport retries 和 failures 均为 0；索引阶段统计的 `max_in_flight` 均为 8。核心索引函数耗时分别为 9.97、11.60、11.65 秒，另有模型加载与进程启动时间。全部 case 的样本数、共享资产、检索导出和 HTTP 状态检查通过。

实际结果见 `_smoke_structural/logs/run.log`、`comparison.md` 和 `completed.ok`。小库实测用于验证流程及调用数，不用于推断全量 Recall 或直接线性承诺全量小时数；全量耗时以正式日志中的速度为准。
