# 已有支撑保护＋额外语义否决：三数据集全量检索

## 方案与边界

新 case 名：`exp4_dependency_binding_plan_prune_dag_package_support_semantic_veto`。

在 `planning,plan_prune,dag_package` 的真实检索结果后，启用 `support_semantic_veto`：

1. 使用先前小样本试验的原始问题联合选择提示词与类型限制，提出至多一次 rank 6–10 与 rank 3–5 的交换。
2. 检查候选引用来自提示词可见的实际源文档，保护已选的获胜绑定来源、问题字面锚点及 DAG 支撑。
3. 用独立提示词检查实体/事件、关系、缺失约束和删除安全性；语义核验看原 Top5，不能把未选候选误当已有证据。
4. 只有原始引用校验、支撑保护和语义核验均通过才应用交换。语义决定仍可能出错，不构成蕴含证明。

Top2、Top10 集合和 rank 11 之后顺序保持不变，因此相对于本次父排序，只能改变 R@5 和 All gold@5。与历史结果的其他指标差异需要检查上游重跑输出。

## 固定条件

- 索引：`outputs/3multi_hop_datasets_results_10_5/shared_indexes/<dataset>`，校验资产哈希并复用。
- 数据集：HotpotQA、2WikiMultiHopQA、MuSiQue，全量各 1000 题。
- embedding：Qwen3-Embedding-8B，batch=4。
- LLM：Qwen3-8B，检索并发=8，索引参数也保留为8；本脚本不重建索引。
- 输出上限2048、temperature=0、seed=0、thinking=False；读取 benchmark 逐题跳数。
- 仅检索，导出逐题 Top10 及 Top200 候选。
- proposer/reviewer 分阶段以8题窗口并发。提示词在请求前检查8192上下文预算，超长时明确记录放弃；HTTP异常会传播。

## 导出与比较

结果位于 `cases/<dataset>/exp4_dependency_binding_plan_prune_dag_package_support_semantic_veto/`：

- `result.json`：逐题检索文档、父/新物理文档 ID、原始 proposer/reviewer 输出与保护/否决原因。
- `report.json`：检索指标、耗时、LLM 请求统计。
- `paired_parent_comparison.json`：本次实际父排序与新排序的严格配对指标、改善/退化题目；不额外调用 LLM。
- `comparison_vs_dag_package.json`：与历史全量 DAG 结果的对比，并标记父级计划/绑定/核验输出差异。
- `support_semantic_veto_validation.json`：排名边界、保护和调用数检查。
- `vllm_http.log` / `http_audit.json`：实际请求日志片段及哈希，避免服务日志后来消失无法检查。

流程先完成父级检索，再显示 `Evidence support/semantic veto` 进度；该阶段耗时计入 `retrieval_seconds`。

## 接入验证

CPU 重放360条先前冻结试验：完整 Top200 排序、支撑保护与语义核验决定全部相同，251次提示词哈希一致。覆盖19次接受交换、8次支撑保护否决后仍核验、22次语义否决。HTTP异常传播、超长提示词零请求、物理文档 ID 错位拒绝均通过。

同一正式脚本在三个真实公共索引上各测试两题，共6题均完成。实际HTTP请求14次，全部200，重试/请求失败均0；包含有效交换和支撑保护否决，实际排名及严格配对指标检查通过。MuSiQue读取逐题2/3跳标签。测试题用于检查流程和分支，不用于估计全量提升；通过后删除独立测试目录及CPU临时文件。

这证明接入保持了先前试验的逻辑；全量效果以本次三个数据集实际结果为准。
