# NV2：依赖闭合修复与统一证据集合选择

## 1. 修复目标与运行模式

本轮修改已有证据核验、覆盖计算和 DAG 选择，不添加检索路线，不重建索引。
新模式为 `evidence_scoring_mode=dependency_joint`，要求 stage=4、正常检索模式和已有 `dag_package`。
`legacy` 保留现有最终方法作对照；上一轮 `dependency` 保留用于复现，新的试验使用 `dependency_joint`。

上一轮三个数据集各96题，最终 Top5/Top10 集合逐题完全相同：R@5/10 没有提升。
HotpotQA 的一题发生根节点从第2名升到第1名，R@1 从0.427083降到0.421875。
原因是仅剩一个通过检查的前置目标时，覆盖增益按这个目标数归一化为1，
导致只支撑桥接关系的文档拿到整题满覆盖奖励。2Wiki 的新评分又提前做了已有 DAG 的相同选择。

## 2. 覆盖按完整依赖计划计算

设完整计划节点为 V，叶节点为 L，选中证据集合为 S。
仅当 S 中存在与获胜绑定一致的字面引用证明，且所有祖先的证明也在 S 中时，节点才能进入闭合集合 C(S)。

```text
节点覆盖 = |C(S)| / |V|
终端覆盖 = |C(S) ∩ L| / |L|
```

分母固定为完整计划，不随本地检查通过的目标数缩小。一个两节点链只支持根节点时，
节点覆盖为0.5、终端覆盖为0；它不能拿到“最终问题已完成”的奖励。
没有可靠终端集合收益时不调整内部排序，避免已有桥接页挤掉强主检索页。
这些覆盖量是模型内部的来源支撑诊断，不等于 benchmark gold Recall。

## 3. 完善现有来源检查

新增检查仅在原检查失败后尝试。仍要求原文引用、答案字面支撑、类型、分支一致性、
关系方向与主体归属；遇到否定、竞争主语、亲属归属、身份冲突或不明确关系继续拒绝。

- 明确标题与首句身份、显式昵称／缩写，以及紧邻句的有主属指代。
- 明确 location/headquarters、creator、broadcast、album artist、mother/capital 等语法关系。
- 数量检查保留单位、数值边界和时间范围；`over 35` 不能证明精确 `35`，
  “before 1983”不能证明“since 1983”。不重写获胜答案，也不扩大引用内容。
- 同一来源可有多个合法证明备选，避免只检查最前面的一个或三个页面。

这是有界本地检查，不能声称一般语义蕴含或百分百正确。它不调用 LLM、embedding 或新检索。

## 4. 统一 Top5／Top10 集合目标

在已有 DAG finalizer 内完成选择，不先做独立贪心评分再做重复包选择。
完整原 DAG 排名作为回退基准，保证保留上一轮已经有效的包选择。

1. 固定原 Top200 集合，收集同一获胜分支的全部合格 proof alternatives。
2. 每页对应一个支持节点 bitmask；计划至多6节点，因此至多64种 mask。
   按文档数量和 mask 做动态规划，避免证明备选的笛卡尔积爆炸。
3. 优先增加完整终端闭合，再比较完整计划节点覆盖；现有闭合节点和选中的支撑页不能丢。
4. 必须严格增加终端闭合才能替换集合。相同覆盖时偏好少换页、原排名及主检索信号。
5. Top5 保留原 Top2；Top10 固定已选 Top5。保留页与尾部保持相对顺序，文档唯一且总集合不变。
6. 新增闭合支撑页传入已有 support guard，后置 semantic veto 不能再把这些支撑换掉。

Top2 保护意味着本轮不主动优化 R@1/2。它解决上一轮不必要的前两位扰动，重点验证 R@5/10。
同一个算法配置用于三个数据集，不按数据集名称、gold、历史分数或失败题编号选取规则。

## 5. 成对实验协议

- HotpotQA、2WikiMultiHopQA、MuSiQue 各96题，沿用上一轮 seed=1031 的同一批样本。
- 按问题可见结构和授权的 benchmark 跳数分层；不是按旧结果选“容易涨分”的题。
- 复用 `3multi_hop_datasets_results_with_nv2_10_8/shared_indexes` 的完整语料 NV2 索引。
- NV2 batch=4、禁止拆批；Qwen3-8B 并发8、输出预算2048、上下文8192、thinking关闭、vLLM比例0.52。
- 默认重新运行 legacy 对照，捕获最外层 finalizer 执行前的原始候选、浮点分数、计划、绑定与分支。
  历史实验仅用于复用匹配的 LLM 响应缓存，通过独立 SQLite backup 复制，不复用其排名。
- 两次独立重算上游，甚至在同一环境中，也可能产生极小浮点差异。本次 HotpotQA 96题有4题的原始
  输入 hash 不同，已导出的上游 trace 和全部最终排名相同；仍未将该轮标为通过严格配对校验。
  最终采用原始输入冻结／回放，继续要求 hash 逐位相等，没有取整或放宽比较容差。
- 优化组真实执行新 finalizer、原有 support/semantic veto 和官方指标评估。它使用同一份原始上游输入，
  不重复 embedding、图搜索、QD/PCQD 或 LLM 规划／绑定，不复制基线最终排名。
  这是固定上游的选择机制对照；候选组耗时不包含上游，不能作为端到端速度提升的证据。
- 快照保存 NumPy 原始类型与数值，校验物理 passage 顺序、问题顺序、运行配置、文件 SHA。
  快照只包含检索输入与模型推断的证据，不包含 gold 或评估指标；gold 在排名完成后仅用于评估。
- 逐题校验评分入口 hash、Top200 集合和可用的上游 plan/bindings/routes/核验输出等。
  未调用核验或进入 dense fallback 时，仅允许两边相同的明确未执行字段缺失；正常分支缺失、
  单边缺失或 null 不通过校验。报告记录这些未执行字段。
- 新 selector 每题必须导出诊断并通过无新增请求、闭合支撑、排名边界验证。
- 先同一脚本每数据集2题、两种模式端到端检查，通过后再跑96题对照；不自动跑全量。

选择与本地核验没有新增模型调用。已有 semantic veto 的提示词依赖最终 Top10，
若排名改变可能新增少量其本来的调用。不同缓存命中率下的总耗时不作为算法加速结论。

```bash
bash /root/PathCondRAG/scripts/run_nv2_dependency_joint_subset.sh
tail -f /root/PathCondRAG/outputs/nv2_dependency_joint_subset_10_10/logs/run.log
```

结果在 `outputs/nv2_dependency_joint_subset_10_10/`；
`summary.json` 汇总 Recall、逐题输赢、分层 bootstrap 与0.01退化门槛；
各 case 的 `dependency_joint_selection_validation.json` 汇总 proof 和闭合覆盖。
