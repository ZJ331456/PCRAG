1）
论文相关工作部分缺少迭代式检索增强生成（Iterative RAG），以及信息检索领域中图自适应排序/自适应检索方向的相关文献。自适应检索方法[1,2,3,4]旨在解决研究者所称召回边界局限（recall boundedness）问题：词法检索或稠密检索存在检索盲区，会漏掉相关文档，并且这些文档在排序阶段无法被重新召回。 为此，这类方法会离线构建语料图，存储语料中每篇文档对应的k近邻相关文档。该语料图为离线一次性构建，只需付出一次构建成本。推理阶段，自适应检索/排序算法遍历该语料图，并利用交叉编码器（cross-encoder）打分，优先挖掘常被基础检索器遗漏的相关文档。该方案几乎不会显著增加推理时延，并且能够大幅提升召回率，在浅层检索场景下增益尤为明显。已有研究[4]证实，在多跳问答任务中，这类方法能够有效检索桥接文档，适配检索增强生成场景。 自适应检索方法主要基于聚类假设：关联性强、相似度高的文档，往往对应同一信息需求。因此，这类方法学习得到的文档间关联相似度以及其他有效信号，能够弥补检索器存在的检索盲区。我认为这类工作是非常重要的对比基线。
2）
除2Wiki数据集外，本文所提方法相比HippoRAGv2并未展现显著性能优势。建议开展统计显著性检验，判断多数数据集上微弱提升是否具备统计学意义，并区分性能增益来源于算法创新，还是实验随机波动。
3）
已有研究[5,6]探索超越单纯语义匹配、基于知识图谱的文档排序方案。我认为这是一组重要基线，作者必须开展全面的文献调研。目前论文的对比实验较为薄弱，没有纳入信息检索不同子方向的相关基线，具体问题如上所述。尽管实验采用了多组不同数据集，但本文忽略了信息检索领域专门解决检索盲区（遗漏桥接实体/桥接文档）的已有工作。
4）
还有多项迭代检索、查询拆解类方法与本文研究高度相关。例如Self-Ask[7]是最早探索生成后续子问题的代表性工作，通过子问题检索桥接段落，完成复杂多跳问答。论文虽在相关工作中简要提及，但并未将其作为基线开展对比。其他相关工作还包括多跳问答场景下的Searchain、DeComp等方法。
5）
建议针对公式（5）开展消融实验：仅依靠路径条件化拆解得到文档排序列表，评估该分支独立效果。另外从表4结果可以看出：相比消融变体**“移除路径提示（w/o Path Hints）”**，本文完整方法的性能提升并不突出；然而路径提示是本文核心创新点之一。

方法具备模块化特性。该方案相当于在查询拆解阶段引入干预模块，下游的检索器、信息融合模块与阅读理解模块依旧采用相对常规的实现方式。

创新程度偏向增量式创新。论文融合了基于图的检索、查询拆解、实体引导的查询重写技术；利用已检索实体构造后续查询这一思路，容易被视作顺理成章的改进，而非根本性创新。
该方法高度依赖初始实体 - 段落图的构建质量。倘若实体抽取环节遗漏桥接实体，整套路径条件机制就可能失效。错误分析结果也证实：图结构不可达是占比最高的错误类型。
论文未充分分析桥接实体识别错误带来的问题。PC-QD 会让子问题变得更加具体，一旦路径提示中的桥接实体出错，会引发检索模型更加笃定地召回错误文档。
每个数据集仅使用 1000 条测试问题。该设置具备实用性，但让人质疑实验结果的统计稳健性，尤其部分数据集上性能提升幅度较小时。

多跳 RAG 存在一个典型缺陷：原始问题无法获知桥接实体，导致查询拆解生成的后续子问题语义模糊，本文针对该重要失效场景展开研究。PathCondRAG 利用图挖掘得到的路径提示锚定子问题，思路直观、架构模块化，同时配有较为合理的消融实验，在多跳问答基准数据集上取得明显性能提升。
但本文的贡献属于增量创新。借助首轮检索得到的实体或路径重写后续查询，是迭代检索、图 RAG 与查询拆解方向很自然的延伸方案；论文未能清晰界定自身工作与已有迭代检索框架、以实体为中心的图检索方法之间的区别。 同时该方法极度依赖初始实体 - 段落图：如果图中缺失正确桥接实体，或是选中了错误的桥接实体，PC-QD 会生成指向明确但存在错误的子查询。作者虽然意识到了这类鲁棒性隐患，但分析深度不足。

总的来说，论文研究动机合理、技术方案可行，但创新度与实验实证支撑力度不足。

本文提出 PathCondRAG，一套面向多跳问答任务、基于图增强的检索增强生成框架。核心思路是利用从图中提取的路径提示约束查询拆解流程；路径提示包含源实体、桥接实体、支撑文本片段以及置信度分值。该方案旨在解决多跳问题中的指代模糊问题，生成依托语料信息的子问题，从而实现效果更优的检索。

优点：
 本文聚焦多跳检索中的一项关键难题：在首轮检索前，模型通常无法获知关键桥接实体，致使常规查询拆解方案稳定性较差。本文将实体指代与桥接实体显式融入检索流水线，能够生成指向性更强、相关性更高的检索结果。
 整体框架阐述清晰，示意图易于理解。
 路径提示的构建思路直观，在基于图的证据信息与查询拆解模块之间建立了合理关联。

不足：
 实验设置需要补充更多细节，同时强化统计层面支撑。论文在每个数据集上选取 1000 条问题开展评测，但未清晰说明选取该样本规模的原因、样本采样方式，也没有论证该子集能否代表原始基准数据集。因此难以评判实验结果是否足够可靠。
 表 2、表 3 未提供统计显著性检验结果。模型相对部分基线的性能提升幅度偏小，且每组实验仅使用 1000 条样本，必须通过显著性检验验证性能增益是否具备稳健性。

最后的meta review是：
本文聚焦多跳问答领域一项重要且具有现实意义的问题：在初始查询拆解阶段，桥接实体尚未获知，难以完成有效检索。论文提出的 PathCondRAG 框架思路直观、研究动机充分。但审稿人提出了多项实质性质疑，综合来看，不足以支撑论文录用。
最核心的问题是基线对比不充分、选用方法偏陈旧。多位审稿人指出：文中将 PathRAG、HopRAG、LightRAG、GraphRAG 列为高度相关竞品，实验却并未纳入对比。作者仅以 “缺少可复现代码” 作为理由，说服力不足，而上述方法均已开源。 同样地，迭代检索类基线仅选用 2023 年的 IRCoT，缺少与 Self-Ask、FLARE、Self-RAG、Adaptive-RAG，以及 Search-R1、RQ-RAG 等近年基于智能体、强化学习训练的检索方法开展对比。
信息检索领域中自适应检索、语料图排序相关基线也存在缺失，而这类方法旨在解决的检索盲区问题，恰好与 PathCondRAG 的目标一致。 另外论文缺少统计显著性检验，进一步削弱实验可信度。每个数据集仅评测 1000 条问题，并且相比 HippoRAGv2 的性能提升大多十分微弱：例如 HotpotQA 数据集上 R@5 指标基本持平；其余数据集涨幅较小，性能增益很可能只是实验随机波动造成。
尽管论文行文流畅、方法机制阐述清晰，并且如实披露效果持平甚至下降的实验结果，值得肯定。但综合以下几点：创新偏向增量改进、基线对比体系不完备、统计层面缺乏严谨性、消融实验与鲁棒性分析不足，本文尚未达到 CIKM 录用标准。
