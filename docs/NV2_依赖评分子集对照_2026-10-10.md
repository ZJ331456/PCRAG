# NV2：已有依赖关系参与评分的子集对照

## 本次改动

本次保留 `planning,plan_prune,dag_package,support_semantic_veto` 流程，只用
`evidence_scoring_mode=dependency` 替换已有证据评分与前缀选择的计算。
默认 `legacy` 仍执行原评分，不改变其文档排序和分数。

优化版先计算原版排序，冻结该排序的 Top200 集合。主检索信号使用进入原版证据选择前的
融合排序分数；它已经包含 PathCondRAG 的查询和路径融合，不是 HippoRAG2 原始排序。

1. **依赖支撑产生覆盖收益。** 只使用获胜分支的现有答案、引用和候选文档。引用须为原文，
   答案须在引用中，主体、关系和答案类型须通过已有本地核验。子节点的收益要求其祖先
   同样有可靠支撑，且相关文档已经被选入前缀；LLM 自报 confidence 不决定加分大小。
2. **减少错误子目标的干扰。** 相同具体主体与关系归并覆盖目标。未核验路线不能产生覆盖收益，
   只给有上界的小额辅助奖励；不再因为每条子查询都把某文档排第一，就给予大额奖励。
3. **保留强主检索信号。** 主排序权重至少为0.6；可靠引用不强制进入 Top5。
   文本冗余只在真实证据支持相同目标时计算，祖先与后代所需的不同证据不会因词汇相似互相扣分。
   没有可靠支撑时完全回退原版排序。选择完成后，尾部保留原版相对顺序。

本地关系核验是有界的语法和主体检查，并非一般语义蕴含保证。对它不认识的关系保守回退，
避免将偏题规划的引用自动视为正确证据。

## 两组与运行设置

- `baseline`：现有最终方法，`evidence_scoring_mode=legacy`。
- `dependency_scoring`：相同流程，`evidence_scoring_mode=dependency`。
- HotpotQA、2WikiMultiHopQA、MuSiQue 各96题，种子1031，共6组；只做检索。
- 每个数据集使用原完整语料和 NV2 公共索引，不重建、不缩小索引。
- 按问题文本可见结构和 benchmark 跳数分层，不用历史成绩或 gold 文档挑题。
  各层尽量保留至少2题，并报告原始均值和按总体层比例校准的差值。
- NV-Embed-v2，embedding batch=4，禁止 OOM 拆批。
- Qwen3-8B，LLM 并发8，输出预算2048，服务上下文8192，thinking 关闭。
- vLLM 显存比例0.52；启动前验证最长输入完整 batch4 和8请求与编码重叠运行。
- MuSiQue 逐题 benchmark 跳数沿用现有协议，属于使用结构标签的条件。

## 控制变量和判定

先运行对照，再将其已完成 LLM 缓存通过 SQLite backup 复制给优化组；不复制排名或结果。
逐题核对规划、绑定、检索轨迹、核验输出与最终评分入口哈希，并检查两组 Top200 集合相同。
共享图、向量、OpenIE 元数据运行前后 SHA256 不得改变。

评分函数本身没有新增 LLM、embedding 或检索调用。但后置 `support_semantic_veto` 的提示词依赖
Top10，排序改变后仍可能产生新的请求。因此这是完整流程的成对对照，不能称为纯 CPU 离线实验，
也不能用两组不同缓存命中率下的耗时判断速度优劣。

输出包括 R@1/2/5/10/20/200、All gold@5/10、逐题输赢、成对分层 bootstrap 区间，以及0.01退化限制。
几十题的正向结果只作为筛选证据；它不能保证全量提升或全量退化小于0.01。
脚本不会自动启动全量。

## 文件和启动方式

```bash
bash /root/PathCondRAG/scripts/run_nv2_dependency_scoring_subset.sh
tail -f /root/PathCondRAG/outputs/nv2_dependency_scoring_subset_10_10/logs/run.log
```

结果：`outputs/nv2_dependency_scoring_subset_10_10/cases/<dataset>/<case>/`。
总体结果：`summary.md`、`summary.json`。
逐题配对与差值：`metadata/<dataset>_paired_comparison.json`。
抽样结构：`metadata/<dataset>_sampling.json`。

同一正式脚本的 `--smoke` 使用完整索引、每数据集2题、两种模式，写入独立 `_smoke` 目录；
通过后删除该目录，保留验证摘要和显存测试报告。

## 启动前实测

- 354项证据模块 CPU 回归、9项抽样与配对验证测试通过。
- vLLM 0.52：13次最长输入/边界完整 batch4 编码通过；8个实际 LLM 请求与编码重叠运行通过，
  没有 OOM、非200响应或 thinking 输出。
- 同一正式脚本的6组端到端检查通过，Top200 集合与上游入口/输出一致；MuSiQue 覆盖2跳和4跳。
  这次每数据集2题的指标差值为0，不作为性能提升证据。
- 临时目录已删除，验证摘要保留在正式输出的 `metadata/smoke_validation.json`。
