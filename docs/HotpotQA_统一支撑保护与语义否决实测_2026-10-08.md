# HotpotQA：统一支撑保护与语义否决的实测

## 1. 当前结论

以三个数据集现有 `exp4_dependency_binding_plan_prune_dag_package` 为对照，这轮已经完成统一机制的小样本比较。

**“已有支撑保护＋额外语义否决”在开发与回归样本上有收益，新的确认样本中 HotpotQA 没有提升。它通过了本次不退化检查，但尚未达到稳定提升 HotpotQA、更没有达到提升 0.04 的目标。当前保留原 DAG package 为全量方案。**

新确认结果是每个数据集 30 题，不能与原 1000 题的指标直接相减：

| 数据集 | 新确认的原 DAG R@5 | 支撑保护＋语义否决 R@5 | 增量 | 新确认 R@10 | 原始/加权八项退化检查 |
|---|---:|---:|---:|---:|---|
| HotpotQA | 0.916667 | 0.916667 | 0 | 0.966667，保持一致 | 通过 |
| 2Wiki | 0.958333 | 0.958333 | 0 | 0.975000，保持一致 | 通过 |
| MuSiQue | 0.730556 | 0.747222 | +0.016667 | 0.833333，保持一致 | 通过 |

MuSiQue 新确认的 All gold@5 从 0.433333 到 0.466667；其余两套数据保持一致。主组合的新确认中有 1 题提高 R@5、0 题下降，发生在 MuSiQue；2Wiki 的两次交换对 Recall 中性，HotpotQA 没有实际交换。

这些结论的范围是本次被测样本及被冻结的候选输出。没有取得“全量三个数据集下降都小于 0.01”的证明。

## 2. 实验如何控制变量

复用以下原检索输出及公共索引：

```text
outputs/3multi_hop_datasets_results_10_5/
  shared_indexes/{hotpotqa,2wikimultihopqa,musique}/
  cases/<dataset>/exp4_dependency_binding_plan_prune_dag_package/result.json
```

本轮直接重放其 Top200 文档、计划、绑定与分支信息，然后做有限的排名修正。没有重构索引、重新编码或运行 QA。原有检索采用的 benchmark 跳数条件保持一致；论文仍需要明确报告这一结构信息使用条件。

- 同一个生成器给出一个候选替换；各对照共用同一响应。
- 原 Top2 固定；候选只能来自原第 6–10 名；被替换文档只能来自原第 3–5 名。
- Top10 文档集合和第 11 名之后的顺序固定。
- 文档 ID 和绑定/计划状态不变，候选不得重复。
- 请求仍是本地 Qwen3-8B、温度 0、seed 0、输出上限 2048、thinking 关闭、并发上限 8。
- 上游 Qwen3-Embedding-8B、embedding batch=4 及完整候选结果保持一致。本轮没有运行 embedding。
- 题目 gold、样本编号和数据集名称不进入算法判定输入或 LLM 提示词。历史检索标签用于离线分层采样和计算指标。
- 每份结果保存代码、来源文件、样本和阶段报告的哈希；另做逐题 CPU 重放验证及 HTTP 日志归档。

**因此 R@1、R@2、R@10、R@20、R@200 以及 All gold@10 保持一致，是此次有限交换的结构性质；这套机制只能改善 R@5 和 All gold@5。** 后续要提高 R@10，需要允许第 11 名之后的证据进入 Top10，另外验证祖先支撑和回退约束。

## 3. 样本与偏差边界

分成三个阶段，三个数据集每阶段使用相同的协议：

| 阶段 | 每套数据题数 | 作用 | 分层权重对应的题池 |
|---|---:|---|---:|
| screen | 60 | 原有开发样本，比较机制 | 289 |
| regression | 30 | 上一轮 typed 方案已观察的确认题，现在用于已知错误回归 | 199 |
| confirmation | 30 | 在剩余题中抽取新的确认样本，冻结后才调用模型 | 169 |

新确认使用 seed=2558，与此前使用的 120 题零交集。按原始结构与历史难度分层，层内随机无放回抽样。三个数据集分别有 4、7、13 个可用层，每个层至少 1 题；权重为 `N_h / (169 × n_h)`。

MuSiQue 的一种 `4hop2` 结构在当前剩余题池中已没有未使用题；全量中有 27 题，原 289 题池仅有 3 题，均已使用。采样文件明确记为 quota=0，没有借用旧题充当新确认。

这意味着：

1. 新确认覆盖当前仍可用的结构/难度层，不能宣称覆盖整个数据集的全部语义情况。
2. 加权结果描述相应剩余题池，不能据此宣称对完整 1000 题无偏。
3. 前两批是开发数据，不能把 60＋30＋30 合成“120 题独立确认”。
4. 这仍是同一 benchmark 上经过多轮开发的探索性验证，不是未经接触的正式论文测试集。

检查原始及加权结果的八项指标：六个 Recall、All gold@5、All gold@10；每一项均要求增量不低于 −0.01。主方案在新确认前登记为 `protected_semantic_veto`，确认之后没有改变其规则或阈值。

## 4. 两个主要机制

### 4.1 已有支撑保护：`evidence_support_guard.py`

保护当前 Top5 中以下文档，禁止把它们作为 victim：

- 原 Top2。
- 原 DAG 已保护的证明来源。
- 当前 winning branch 中已有绑定的字面来源，检查绑定一致性及引文出处。
- 原题明确提到的具体文档标题对应的已选 passage。

即使某个来源没有达到 DAG promotion 的条件，其已存在的支撑也可保留。相同标题的不同 passage ID 分别处理。

这是一种保留已有信息的约束，不会把旧绑定重新判为正确。错误的旧绑定也可能被保护，因此可能拦掉有效改进；没有进入 proof、也没有原题标题的隐含祖先仍可能漏掉。

### 4.2 额外语义否决：`evidence_semantic_swap_gate.py`

另一次同模型请求只看原题、原 Top5、未选候选和固定替换 ID，不看生成器的理由、置信度或引文。它判断四件事：

1. 是否针对原题要求的正确主体、事件、时间和含义。
2. 根文档与候选是否提供方向正确的关系。
3. 候选是否提供**原五篇缺少**的必要事实，包括最后请求的关系或属性。
4. 移走 victim 是否丢失中间事实或祖先支撑。

四项都必须明确为 true，并检查实际 ID、完成状态和解释字段。

该对照将“语义判断”和“再次构造出处证明”分开：**原替换提案仍必须通过原选择器的严格字面引文与排名检查。审阅器生成的引文不用于建立证据，也没有将它的错误引文偷偷修成正确原文。**

这是额外的模型否决，不能称为严格的关系蕴含证明。两次请求使用同一个模型，误差可能相关；模型甚至可能把共同话题误判为真正关系。源引文真实也不等于主体归属和关系方向正确。

| screen 60 | 2Wiki | 0 | 0 | 0 |
| screen 60 | MuSiQue | +0.005556 | +0.013889 | +0.005556 |
| regression 30 | HotpotQA | +0.016667 | +0.033333 | +0.016667 |

| regression 30 | MuSiQue | 0 | +0.016667 | +0.027778 |
| confirmation 30 | HotpotQA | 0 | 0 | 0 |
| confirmation 30 | 2Wiki | 0 | 0 | 0 |
| confirmation 30 | MuSiQue | +0.025000 | +0.016667 | +0.016667 |

|---|---:|---:|---:|

| regression | +0.014238 | 0 | +0.020101 |
| confirmation | 0 | 0 | +0.016765 |

### 如何判断组件价值

- **出处保护确有防退化作用。** MuSiQue 回归中，它单独挡掉 2 次原始有害交换，但仍放行 2 次有害交换；其加权 R@5 为 −0.013400，单独使用不满足本次门槛。
- **语义否决补充了保护器未识别的错误。** 同一回归集上，它单独挡掉 3 次有害交换；剩余 1 次由保护器挡掉。组合挡掉全部 4 次原提案中的有害交换，并保留 2 次有效交换。
- **组合存在保守代价。** HotpotQA 回归中，保护器挡掉 1 次按 gold-document 指标有益的交换，使 +0.033333 变为 +0.016667；MuSiQue 新确认中，语义否决也挡掉 1 次指标有益的交换。
- **2Wiki 的零增量仅表示被测样本的 Recall 中性。** 少量文档交换对已完整召回的题目没有增加指标，不等于组件对整个数据集完全无作用。
- **没有获得稳定提高 HotpotQA 的新确认依据。** 开发/回归中的提升不能覆盖新确认的零增量。

按 gold-document Recall 有益的交换，也不必然改善语义证据或 QA。例如相同事实可能分布在 gold 和非 gold 文档中，语义保留与 gold 文档计数需要分别评估。

## 6. 严格核验器的负结果也保留了

还测试了几个严格二次证明版本，分别保存，不合并到主结果：

| 版本 | 具体变化 | 已完成范围 | 结果 |
|---|---|---|---|
| v1 | 独立关系/替换核验，要求真实主体、共同桥接、字面引文 | 每数据集 60 开发＋30 回归；8 题 pilot 是开发子集 | 未放行替换，指标不变 |
| v2 | 证据前缀由 1400 增至 2000 字符，移除默认 false JSON 示例，要求三个真实 ID | 每数据集 60 开发及 8 题 pilot | 未放行替换，指标不变 |
| v3 | 明确区分原 Top5 与未选候选，要求原集合缺失事实与候选新增事实 | 每数据集 60 开发及 8 题 pilot | 未放行替换，指标不变 |
| source units | 让模型选择原文句子编号及共同字面实体选项，代码还原连续来源区间 | 每数据集 8 题 pilot | 未放行替换，指标不变；存在不存在的句子 ID 等格式问题 |

不同版本没有逐一运行新的确认题；没有把这些负结果换成另一个有利子集的结果。语义否决使用 v3 的同一提示与缓存响应，因此其 60 题开发对照没有新增 HTTP 请求。

严格 v1 的一些输出逐字复用了模板解释，统一给出四个 false；v2 改善了具体解释，但必要事实判断仍经常把候选混入原集合。v3 改善了语义判断，仍会返回省略号引文、错误桥接字段。句子 ID 版本避免了抄写长引文，却还会选择不存在的 ID，严格解析如实拒绝。

这些结果支持“当前小模型重新构造完整证明不够可靠”的局部判断，不能证明原文约束或关系核验这一研究方向无用。之后可测试受约束的句子 ID 解码、独立关系判别模型或训练出的证据兼容性评分，但需要额外的等预算对照与独立验证。

## 7. 查清的具体失败原因

### 7.1 证据被字符截断隐藏

MuSiQue #889：`Imperialism` 中 Mao Zedong 的相关句子位于原文 1531–1652 字符。原选择器只提供前 1400 字符，模型看到的主要是 Khrushchev 段落。

它随后提出 Khrushchev→Truman 的替换，移走真正包含 Mao 向 Politburo 宣布干预朝鲜战争的段落。新的核验视图提供前 2000 字符，能够看见该 Mao 句；保护器单靠原来源 ID 仍不能自动保护其他段落里的终端事实。

更长窗口提升的是证据可见性，不能保证模型会正确理解事实，不能仅凭这一个样例宣称扩大窗口就提高整个检索性能。

### 7.2 字面引文真实，关系仍然错误

MuSiQue #721：模型把 Germanic tribes 的地区背景和 Gallic tribes 在 390 BC 入侵 Italy 的描述连起来，并移走 Rössen culture 的正确祖先证据。两段引文确实存在；它们不足以证明原题要求的同一批部落和同一次事件。

这说明新增保护与语义核验需互补。仅增加重试或更严格 JSON 解析不能解决关系错误；单纯按 benchmark≥3 回退也不能解决这条二跳题。

### 7.3 新 HotpotQA 确认没有提升：有效提案没产生

新确认 30 题中有 5 题 Top5 不完整：

| query_index | 缺失 gold 排名 | 主要原因 |
|---|---:|---|
| 165 | 11 | 正确证据在 Top10 外；提案还把一段 Remix 引文错配到另一个 ID，严格出处校验拒绝 |
| 377 | 22 | 正确发布商 Nordcurrent 在 Top10 外；生成器提出另一家公司的国家，语义否决识别主体不符 |
| 579 | 7 | 正确 Alfred Jodl 文档已在池中，生成器却选择 Ludwig Beck，并返回不匹配候选的引文 |
| 626 | 7 | 正确 Frank Ocean 文档已在池中，生成器选择 `12 Odd Future Songs`；其引文没有建立所声称的 Frank Ocean 成员关系，原题锚点保护也阻止删除 Odd Future |
| 951 | 6 | 正确 Avril Lavigne 文档已在池中，当前 typed gate 因 `answer_type:number` 直接跳过 |

此批生成器收到 18 个符合范围的提示，仅产生 2 个通过原字面校验的提案；它们在 gold Recall 上均中性。**提高后续否决器的放行率无法补出一个没有产生过的正确候选提案。**

#626 的语义审阅仍会把相关话题误认成真实成员关系；这也是为何不能把语义否决称为严格的关系证明。

## 8. 下一步更值得做什么

下一轮应优先改候选生成与依赖实体对齐，使用新的开发/确认协议，而非在已经查看的确认 30 题上继续调参数后宣称独立提升。

### 优先一：由已绑定实体约束候选事实

对所有数据集采用同一规则：先从根证据中得到实际桥接实体，再围绕该实体选择满足下游关系的候选。

- #579 应围绕 Alfred Jodl 的任职关系，排除“另一位德国将军”的相似传记。
- #626 应围绕 Frank Ocean 的成员关系，排除“另一个 Odd Future 专辑”的一般介绍。
- 来源、主体、关系、事件条件都需要进入约束，不能仅加全文关键词或文档标题分数。
- 旧绑定也可能错，需要保留原题一致性检查及回退；不能默认有字面引文的旧绑定就正确。

这与 exp4 的依赖绑定主线直接关联：让变量绑定决定可接受的证据事实，而不是在相似话题候选之间再次让模型自由选择。

### 优先二：区分单主体数值属性与聚合推理

当前 `answer_type:number` 的整体禁用过宽。#951 是“某位已确定歌手的专辑销量”，属于实体→数值属性，不是多实体集合计数。

可以尝试在唯一、已建立的主体条件下允许数值属性证据；对集合计数、比较和缺失主体条件继续回退。规则应跨数据集统一，并专门检查 MuSiQue 的日期、数值和多祖先情形，避免为 HotpotQA 打开通用的高风险通道。

### 优先三：将 Top10 内整理与 Top10 外补证分开

#165、#377 的正确文档在 11/22 名，当前有限交换无法恢复它们。下一轮可把实际候选视图扩大到 Top20/Top50，同时保留祖先支撑约束、有限替换数量及原排名回退；分别报告 R@5 与 R@10 的变化。

当前完整 HotpotQA 的 R@10=0.9675：

- 加 0.04 得到 1.0075；相对加 4% 得到 1.0062，均超过指标上限。
- 理论最大绝对增量只有 0.0325。
- 固定现有 Top200 时，其 R@200=0.997，可恢复上限至多为 +0.0295。

因此 HotpotQA 的目标应分别设定：R@5 的 +0.04 仍可作为挑战目标；R@10 需要按剩余错误可恢复比例评价，不能要求超过 1。可优先研究 +0.005～0.015 的 R@10 增量，但这只是下一轮的验证目标，不是结果预报。

这些方向与多跳链路检索、证据链评分及整体证据选择的研究相关，例如 [MDR](https://arxiv.org/abs/2009.12756/)、[PromptRank](https://aclanthology.org/2023.acl-long.885/) 和 [Beam Retrieval](https://aclanthology.org/2024.naacl-long.96/)。本文的同模型聊天审阅与这些方法的具体评分/搜索机制不同；相关论文不能替代本地消融证明。
