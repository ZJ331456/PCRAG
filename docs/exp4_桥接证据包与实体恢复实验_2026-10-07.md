# 以 plan_prune 为对照的桥接证据实验

## 1. 用户最新全量结果

三套数据集均为现有本地评估文件的 1,000 题，下面数值来自 `cases/<dataset>/exp4_dependency_binding_plan_prune`。本轮不重新构建索引。

| 数据集 | 原 exp4 R@5 | plan_prune R@5 | 增量 | 原 exp4 R@10 | plan_prune R@10 | 增量 |
|---|---:|---:|---:|---:|---:|---:|
| HotpotQA | 0.92200 | 0.92100 | -0.00100 | 0.96750 | 0.96750 | 0 |
| 2WikiMultiHopQA | 0.89575 | 0.93550 | +0.03975 | 0.90900 | 0.97775 | +0.06875 |
| MuSiQue | 0.74150 | 0.74175 | +0.00025 | 0.8364167 | 0.83700 | +0.0005833 |

2Wiki 的 R@5 增加 3.975 个百分点，尚比严格的 4 个百分点少 0.025 个百分点；R@10 已超过 4 个百分点。HotpotQA 的 R@1 下降 0.0015、R@2 上升 0.001、R@5 下降 0.001，其余三个 Recall 不变；MuSiQue 六个 Recall 没有总体下降。以上支持保留 plan_prune，但不能把该增益归给本轮新增模块。

这些全量运行使用大量既有 LLM 缓存。不能直接根据耗时与较冷缓存的原始实验做效率结论。本轮保存全量结果文件哈希，并汇总同题历史指标供参考；新增收益只对同一批样本上重新执行的 plan_prune 计算。

## 2. 四种筛选配置

| 配置名 | 内容 | 新增作用 |
|---|---|---|
| baseline | planning + plan_prune；canonical_refs、question_structure | 当前对照 |
| package | baseline + 证据包选择 | 局部调整已有 Top10 内的排序 |
| bridge_recovery | baseline + 桥接实体恢复 | 修复没有成功绑定的局部证据或依赖链 |
| bridge_package | baseline + 两者 | 检查恢复后是否仍需要成组选择 |

### A：证据包选择

实现文件：`src/pathcondrag/evidence_package.py`。

1. 先完成原来的检索和选择，再检查已有 winning branch 的字面引用、实体绑定、关系方向及必要祖先支撑。
2. 仅考虑已有第 6～10 名的证据；第 1、2 名固定，最多交换两个第 3～5 名的位置。候选集合、Top10 集合、Top200 集合均保留。
3. 有效包必须存在明确的原文关系支持。当前覆盖有直接源支持的地理归属、改编作品及创作者关系，以及创办者身份页与所问演员作品条件同时满足的情形。
4. 不仅因为同名、同页或 LLM 高置信度就提升文档。不具备明确规则、缺少选中的祖先或缺少空闲位置时保持原排序。
5. 现版本只作用于一至两节点的串行或单节点条件；不替换已展开的并行比较路线，不宣称解决任意语义蕴含。

**它没有额外 LLM 请求，也没有额外检索。R@1、R@2、R@10、R@20、R@200 在同一检索结果上应完全不变；R@5 仍可能因交换损失真实相关文档，所以必须用配对指标筛选。** 覆盖范围有意保持有限，不能预先断言会提升 4 个百分点。

### B：桥接实体恢复

实现文件：`src/pathcondrag/evidence_bridge.py`。

**零请求的身份引用恢复：** 原核验已经返回有效绑定时完全沿用原结果。只有原核验未形成有效绑定时，复用原来两次核验产生的候选；要求原引用确实是原文连续子串，并由同一文档的标题/首句身份解释姓氏、短名字或紧邻代词。拒绝不同姓名前件、家属属性转移、否定和缺少所问关系对象的引用。扩大后的引用仍必须是同一原文连续片段，长度上限 1,500 字符，再经过原字面核验。这个检查是有限关系的源文支持判断，不是通用语义正确性保证。

**受限的缺失桥接修复：** 原依赖检索先跑完；已完成的链保持原样。对于目前明确识别的两类未解决关系，允许一次修复规划：成员/角色→指定作品→播出机构，以及产品→代言球员→国家队。修复须保留输入年份、国别、作品/产品和角色条件，使用 `r1/r2/r3` 字母前缀 ID 与字面依赖占位符。

每题最多新增一次修复规划请求，之后修复节点会有检索和原有核验请求；**不是总共只多一次 LLM 请求**。仍使用现有并发 8、节点上限 6、深度上限 4、共享检索次数上限 20。完整修复失败则保留原 DAG 和候选，只记录已消耗的调用。当前没有穷举全部多值球员分支，也不把这两类规则描述成覆盖全部桥接问题。

### A+B：控制 LLM 输出后的组合

A 是检索完成后的局部选择，因此组合试验必须复用同阶段、同题目的 B 的规划、核验和修复输出。脚本冻结 B 的私有缓存，再启动 A+B，逐题校验 plan、bindings、branch_scores、routes、规划与核验输出和调用计数相等，且 A+B 不产生新的 HTTP 调用。通过后才把组合排序差异归因于 A。

如果组合进入确认阶段，先运行 B 再运行 A+B；必要时 B 只是组合的父对照，不能因被迫运行而被标记为有效模块。

## 3. 采样、判断和运行范围

- 先运行三个数据集各 2 题的 baseline、baseline_replay 和 A+B，共 9 组实际集成测试。固定样例只验证机制，不用于收益筛选，且排除在后续样本外。
- 筛选为每套数据集 60 题，四种配置共 12 组；确认另取不重叠的 30 题，对最多两个候选或必要的父对照运行 6 或 9 组。如果没有信号，确认跳过。合计固定 21 组，最多 30 组。
- 排除此前原始筛选、确认及 `structure_representative`、`failure_focused` 等轮次已使用的开发题。采样按主要问题结构及跳数分层，在采样报告中记录覆盖与不可避免的缺口；不根据检索成功/失败选题。
- 同时报告原始样本均值及按主分层人口比例校准的均值。几十题只能给出探索性信号，无法保证无偏、显著性或全量稳定提升；三个本地评估文件此前也已经用于开发。
- **两个估计口径下，各数据集的 R@1/2/5/10/20/200 相对同题 baseline 都不得下降超过 0.01。** HotpotQA 至少一个 R@5/R@10 指标必须在两口径下都上升，才进入确认。不能把 2Wiki 既有 plan_prune 增益重复计入。
- +0.04 的大幅提升目标单独报告，微小正向信号不标成达标。HotpotQA 对照 R@10=0.9675，理论最大绝对提升只有 0.0325，不能声称该项达到 +0.04。
- 这轮仅小样本检索；脚本不会自动启动全量或 QA。筛选、确认结果留存，私有索引副本在完成验证/缓存快照后清理，公共索引不改。

运行固定：Qwen3-Embedding-8B、embedding batch=4、LLM/索引并发=8、max_new_tokens=2048、thinking=false；沿用现有本地 vLLM 服务。MuSiQue 按授权读取逐题 benchmark 跳数，其余数据集按当前 benchmark 规则处理。问题结构标签和 gold 仅用于离线评估/采样，不进入新增模块。

## 4. 命令和产物

```bash
# 同一正式脚本：先集成测试，随后可恢复到筛选及确认
bash /root/PathCondRAG/scripts/run_exp4_bridge_trials.sh --mode smoke
bash /root/PathCondRAG/scripts/run_exp4_bridge_trials.sh --mode all

# 本轮独立启动日志
tail -f /root/PathCondRAG/outputs/3multi_hop_datasets_results_10_5/logs/launcher_bridge_support.log
```

主要产物：

- `metadata/exp4_round2_selection_bridge_support/selection.json`：冻结配置、样例 ID、哈希、进度、历史参考、配对增量、筛选结论。
- `metadata/exp4_round2_selection_bridge_support/sampling/*.json`：分层采样覆盖。
- `_exp4_round2_trials_bridge_support/{smoke,screen,confirmation}/<dataset>/<profile>/`：Top10 详情、Top200 候选、逐题证据轨迹、报告及校验标记。

## 5. 当前验证状态

代码层面的检查与实际 LLM/embedding 集成检查分别记录。不得用固定成功样例或 CPU 回放的少数提升宣称新模块已经有效；有效性由本轮配对筛选和独立小样本确认结果决定。

2026-10-07 实测：232 项检索组件检查、57 项实验脚本检查通过；同一正式脚本的 9 组实际接入测试均完成。三个数据集的 baseline_replay Top10 均与同阶段 baseline 一致，HTTP 无非 200 响应、请求失败或重试。固定 HotpotQA 样例分别触发源文支持的第 6→5 名交换，以及成员→作品→播出机构三节点修复，组合运行新增 4 次 HTTP 请求全部成功；MuSiQue 接入样例按 manifest 为逐题 3 跳和 4 跳，继续使用 benchmark 跳数。

筛选尚未完成时，不判定 A、B 或 A+B 有效。后续分析必须同时比较 A−baseline、B−baseline、A+B−B 和 A+B−A；组合超过 baseline 不能单独证明两个模块分别贡献。等效排序优先考虑删去没有独立或交互收益的模块，并结合新增请求成本判断。
