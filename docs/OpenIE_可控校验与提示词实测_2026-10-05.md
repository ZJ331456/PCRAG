# OpenIE 可控校验、开销优化与 Qwen3-8B 提示词实测

## 1. 使用方式

在原构建命令后增加：

```bash
--openie_strict true --openie_prompt_version optimized
```

需要最终抽取失败后继续构建时：

```bash
--openie_strict false --openie_prompt_version optimized
```

支持 `scripts/build_shared_index.py`、`scripts/eval_dataset.py` 和
`scripts/new_index_compare.py`。最后一个脚本也接受参数的连字符拼写。
默认值为 `true` 和 `optimized`。仅修改 PathCondRAG，原始 HippoRAG 源码未改。

| 开关 | 行为 |
| --- | --- |
| `true` | 抽取及最终核验协议未完成，则保存检查点、诊断和失败统计，中止图发布 |
| `false` | 仍然抽取、重试及核验；最终失败的关系排除，保留 chunk 文本及向量，警告后继续构图 |

`false` 的继续运行方式与 HippoRAG 的容错诉求相同，但不意味着恢复原生抽取算法或速度。
它只改变最终失败的处理方式，不关闭额外质量检查。语料不一致、损坏的检查点、
图与向量不一致等错误仍然会中止，避免发布无法解释的索引。

经原文核验确认没有关系的 chunk 允许为空；强行要求任何文本都抽到非空关系会诱发编造。
失败诊断保留 `openie_metadata.publication.excluded_triples`、原始响应和失败标记，
不会伪造 `semantic_verified=true`。统计见索引目录的 `openie_publication_report.json`。

## 2. 本次优化与成本

### 2.1 实际修复了固定三字段语法约束

真实测试发现，当前 xgrammar 0.1.18 将普通数组的 `minItems=3/maxItems=3`
编译成允许任意长度的数组。CPU 语法接受测试证明，原语法同时接受 2、3、4、5 字段。
这也是使用 structured output 后仍出现四/五字段关系的原因之一。

修复将固定长度数组转换为等价 `prefixItems` + `items=false` 再编译。
新测试确认仅接受三字段，并仍允许 `{"triples":[]}` 表示没有候选关系。
此转换同时适用于固定数量的核验记录，不改变公开 JSON 验证 schema 的语义。
实现位于 `index/openie/openie_structured_output.py`，版本已更新。

严格流程第一次三元组请求就使用结构约束，减少先生成错误格式再纠正的请求。
合法 JSON 仍然不能证明事实正确；谓词为 `and`、对象取错分句等问题继续由质量检查处理。

### 2.2 NER 只细分失败原文范围

Michigan 长表的初始 NER 在 512 tokens 下截断；原恢复仅按句子/换行分段，
没有句号的长表正文仍是一个大段，重复重试后仍然失败。

现在只把失败范围继续按原始边界细分，成功范围立即保留。记录完整原文 offsets、
成功叶片、失败父片和未处理尾部；只有逐字符覆盖全部输入才标记完整。
累计请求上限 64（含此前尝试）、最大细分深度 12。超过上限或无法再细分仍明确失败。
因此它是有界恢复，不是无限重试，也没有把缺失尾部当作成功。

后续检查点可以复用已成功叶片，只请求未完成范围。正常成功的 chunk 不进入该流程。

### 2.3 减少重复计算和无效缓存重试

- 恢复提示带尝试编号，避免相同失败反馈反复命中同一个坏响应缓存。
- 精确 prompt token 计数在预检查与相同实请求之间复用，内容变化会使缓存失效。
- 语法编译仍按完整 schema 缓存，不按可变对象身份缓存。
- 模板管理器复制模板后再映射角色，不再修改模块内保存的原始模板。

实测旧探针中，CPU tokenization 总计约 0.54 秒，HTTP 请求总计约 99.56 秒；
冷加载约 0.49 秒，其余通常 1–7 毫秒。主要瓶颈是 LLM 生成及核验，CPU 缓存不是大幅加速来源。

NER 上限仍为 512，三元组与证据核验上限仍为 2048，context 仍为 8192，thinking 关闭。
生产阶段 worker 上限仍为 8；测试只用少量并发，没有提升生产并发来换取速度。
embedding 配置和检索算法未变，测试没有加载 embedding 模型或运行全量实验。

## 3. 原提示词和优化提示词

| 版本 | NER | 三元组 |
| --- | --- | --- |
| `origin` | `prompts/templates/origin_ner_prompt.py` | `prompts/templates/origin_triple_extraction_prompt.py` |
| `optimized` | `prompts/templates/ner.py` | `prompts/templates/triple_extraction.py` |

`origin` 是此次优化前的 PathCondRAG 提示词。原三元组示例也引用独立保存的原 NER 示例，
不会因为优化 `ner.py` 被间接改变。

优化重点：单键 JSON、去重复、并列主体分别成事实、明确共享关系的范围、保留归因、
属性对象来自同一断言而不拼接下一分句、表格缺失字段不从邻居补值。
示例使用虚构人物，不复制实际失败样例的姓名或数据集问答标签。

Randy 样例的最终输入 token 对比：

| 阶段 | 原版 | 最终优化版 |
| --- | ---: | ---: |
| NER | 308 | 314 |
| 三元组 | 766 | 648 |
| 合计 | 1074 | 962 |

合计减少约 10.4%。NER 多出的 6 tokens 用于明确日期、单位和去重复要求。
这只是输入长度变化，不能直接换算成完整索引耗时下降比例。

## 4. 真实测试结果与限制

输出均在 `outputs/openie_prompt_probe_20261005/`，没有修改已有共享索引。
固定 Qwen3-8B、seed=42、temperature=0、相同结构语法和输出预算，无 SQLite 响应缓存。
A/B 轮换先后，保存原文、请求、响应、token、耗时、finish reason 和提示词/实现哈希。
样例包含四条真实历史失败和一条真实属性回归样例；不是五条随机普通段落。

### 最终 Randy 完整严格抽取流程

见 `final_pipeline/full_pipeline.json`：7 次真实请求，约 70.63 秒；15 个候选经生产
协议审计后保留 14 个，`verified_complete=true`。检查点重放新增请求 0，结果一致。
这里测试了真实 NER→三元组→所有候选核验→检查点，不包含 embedding 和完整图构建。

人工复核仍发现机器核验误放：将 Sharon 的 `née Kimble` 当成 married name，
将姓名来源简化成 Trey Parker 而非其父母名字，以及评价关系缺少被评价目标等。
机器核验也存在误拒真实关系的情况。这说明当前小模型审计并不等于事实真值判定。

长表 NER 新恢复结果见 `bounded_ner_recovery/ner_recovery.json`；旧恢复失败的实测
也保留在根目录 `ner_recovery.json`，便于区分提示词变化和恢复代码变化。
新版恢复在 61.16 秒、10 次 HTTP 200 请求后完成，得到 24 个去重实体，4 个成功
原文范围连续覆盖 `[0,37]`、`[37,215]`、`[215,728]`、`[728,1242]`。
成功叶片重放新增请求为 0，实体一致。旧版本约 60.59 秒、8 次请求后仍失败。
因此这项修复解决了失败，不能把它描述为该样例的耗时下降。

最终相关 CPU 回归共 309 项，0 失败，1 项可选依赖检查跳过；配置入口帮助检查通过。
测试服务在实测结束后已停止，未启动全量后台或生成新完整共享索引。

## 5. 如何解释“严格”与“加速”

**严格控制发布协议，LLM 语义错误仍可能漏过。** `true` 使未完成、截断、格式错误或
核验协议失败的结果阻止发布；它不能保证判定为 supported 的每个事实都真实、
所有原文事实都已被抽取，也不能保证 NER 完整召回全部实体。

每个 chunk 至少要做 NER、三元组抽取；当前额外对候选关系执行原文核验，
通常每批最多 4 条，关系多时要多个请求。完整严格流程比原生 HippoRAG 更慢是预期成本。
`false` 不关闭这项工作，因此不是速度开关。

本次通过减少格式错误、改进困难样例提示、细分真正失败范围、复用成功阶段来降低
无效耗时，没有降低 token 预算、提高并发或跳过核验。后续若要大幅降低核验请求数量，
需要单独研究核验协议及其误放/误拒率，用人工标注源内事实作验证；不能直接宣称
“少核验但结果一定不变”。同样，本轮没有检索/QA 实验，不能据此宣称 Recall 提升。

提示词、语法与 NER 恢复版本写入质量身份。之后要比较效果，请在新目录重建索引，
不要把旧提示词的检查点或图当作新提示词结果。
